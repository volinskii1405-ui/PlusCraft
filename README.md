# PlusCraft

Воксельная sandbox-игра на **Rust + Vulkan** (`ash`) с собственными механиками
горного дела: обвалы пород, резонансные кристаллы, выгорающий свет, динамика
воды, мутации мобов на глубине.

> Предыдущая версия проекта (C++/OpenGL MVP) сохранена в `legacy-cpp/`.

## Сборка

Нужен Rust stable (1.80+). Vulkan SDK **не обязателен**: если в системе есть
`glslangValidator` (или `glslc`), `build.rs` компилирует шейдеры из `shaders/`,
иначе берёт готовые SPIR-V из `shaders/spv/`.

```sh
cargo build --release
./target/release/pluscraft
```

Упаковка архива для Linux (бинарник + ассеты + настройки + README):

```sh
scripts/package.sh stage1     # -> dist/pluscraft-stage1-linux-x86_64.tar.gz
```

Перекомпиляция шейдеров в `shaders/spv/` (нужен `glslangValidator`):

```sh
scripts/compile_shaders.sh
```

Для запуска нужен драйвер Vulkan 1.1+. Библиотека `libvulkan.so.1`
загружается динамически, поэтому при её отсутствии игра выводит понятную
ошибку, а не падает при старте.

## Выбор технологий

* **`ash` вместо `vulkano`.** `ash` — тонкие привязки без рантайм-проверок:
  полный контроль над синхронизацией (кадры в полёте, отложенное удаление
  буферов), раскладкой памяти и пайплайнами, нулевой оверхед. Для воксельного
  движка, где каждый кадр рисуются сотни чанков и постоянно загружаются новые
  меши, это важнее удобства `vulkano`. Весь `unsafe` изолирован в
  `src/renderer/` и прокомментирован.
* **`gpu-allocator`** — подаллокация памяти (чанков сотни, лимит
  `maxMemoryAllocationCount` обычно 4096).
* **`winit` 0.30** — окно и ввод; **`glam`** — математика;
  **`fontdue`** — растеризация шрифта (кириллица в интерфейсе).
* **Шум** — собственная реализация Simplex 2D/3D (`src/world/noise.rs`).
* **`serde` + `bincode` + `lz4_flex`** — сохранения; **`toml`** — настройки;
  **`ron`** — рецепты.

## Архитектура

```
src/
  main.rs            — цикл событий winit
  renderer/          — Vulkan: контекст, swapchain, пайплайны, текстуры, кадры
  world/             — блоки, чанки, шум, биомы, свет (flood fill), мешер
  assets/            — процедурные текстуры (PNG-атлас) и шрифт
  ui/                — построение геометрии интерфейса
  settings.rs        — settings.toml, привязки клавиш
  camera.rs, item.rs, paths.rs
shaders/             — GLSL (+ shaders/spv — готовый SPIR-V)
```

### Рендер

* Обратный Z (reverse-Z) с бесконечной дальней плоскостью: высокая точность
  глубины на больших дистанциях.
* Рендер относительно камеры: позиция игрока хранится в `f64`, в шейдер
  попадают только смещения чанков относительно камеры — нет дрожания
  вершин вдали от начала координат.
* Вершина чанка — 20 байт (позиция в 1/16 блока, слой текстуры, UV, нормаль,
  AO, свет неба и блоков, флаги, тинт биома).
* Один общий индексный буфер для квадов.
* Проходы: небо (полноэкранный треугольник с солнцем, луной и звёздами) →
  непрозрачные чанки (front-to-back) → сущности → полупрозрачные чанки
  (back-to-front) → линии → UI.
* Текстуры: атлас `assets/textures/blocks.png` (сетка тайлов 16×16) загружается
  в `sampler2DArray` — каждый тайл в своём слое. Это позволяет
  greedy-квадам повторять текстуру (`REPEAT`) и даёт чистые mipmaps без
  «протекания» соседних тайлов, что неизбежно в плоском атласе.
* Валидационные слои включаются только в debug-сборке.
* Корректная обработка изменения размера окна, свёрнутого окна и
  `VK_ERROR_OUT_OF_DATE_KHR`.

### Освещение

Свет (небесный и блочный, 0..15) считается BFS-заливкой на фоновом потоке при
мешинге чанка по окрестности 3×3 чанка (центральный чанк + 15 блоков
отступа). Поэтому свет на границах чанков всегда согласован, а пересчёт при
установке/разрушении блоков сводится к перемешиванию затронутых чанков.
Плавное освещение и ambient occlusion вычисляются по вершинам; greedy meshing
сливает только грани с одинаковыми AO/светом во всех углах.

## Уникальные механики

Реализовано пять механик; все проверяются юнит-тестами и `--selftest`.

### 1. Нестабильные породы и крепи (`src/mechanics/cavein.rs`)
**Как работает.** Камень, руды, булыжник и глубинный камень — неустойчивые
породы. После того как игрок добывает блок, проверяются блоки свода рядом:
если блок «висит» (снизу пусто), до ближайшей опоры по своду (клетки с
твёрдым блоком под ней) не меньше 3 блоков и в радиусе 4 нет **крепи**, то с
вероятностью 30% (не более 3 блоков за раз) он «трещит»: на экране
предупреждение, камера дрожит, и через 1,5–3,5 с он вместе с неустойчивыми
блоками над ним падает, раскалываясь на гравий и булыжник. Попавший под
обвал игрок получает урон. Крепь (4 шт. из досок и палок) удерживает свод;
поставленная до срабатывания — отменяет обвал. Отключается в настройках.

**Зачем.** Превращает копание в инженерную задачу: широкие залы и длинные
штреки требуют планирования, крепей и ресурсов на них, а заброшенные шахты
мира не случайно полны крепей. Узкие туннели (1–2 блока) безопасны — у
игрока всегда есть выбор между скоростью и надёжностью.

### 2. Резонансные кристаллы (`src/mechanics/resonance.rs`)
**Как работает.** Резонит — собственная руда (глубина 4–44, растёт на стенах
пустот), светится сам (уровень 7). Если добыть блок в радиусе 4 от
резонита — или сам резонит — кристалл отзывается **эхо-импульсом**: волна
расходится от кристалла и на 7 с подсвечивает сквозь породу пустоты
(голубые маркеры), руды (каждая своим цветом), воду и лаву. Из осколков
резонита, медного слитка и палки делается **Резонатор**, который вызывает
импульс радиусом 18 по ПКМ (прочность 64, перезарядка 4 с). Но эхо слышат
существа: враждебные мобы в радиусе 36 блоков идут к источнику звука.

**Зачем.** Даёт осмысленную разведку вместо слепого копания и при этом
цену за информацию — каждый импульс собирает вокруг вас мобов.

### 3. Свет как ресурс (`src/mechanics/torches.rs`)
**Как работает.** Факел горит ограниченное время (по умолчанию 12 минут,
`gameplay.torch_burn_minutes`), затем становится «прогоревшим». ПКМ углём
по факелу — дозаправка (до 150%), по прогоревшему — зажечь снова. Запас
топлива виден при наведении. В абсолютной темноте (освещённость 0 с учётом
времени суток) через 4 с наступает **страх темноты**: замедление на 30%,
ускоренный голод, затемнение краёв экрана. **Мракоед** появляется только в
полной тьме и гасит факелы вокруг себя. Постоянный свет даёт лишь дорогая
резонитовая лампа.

**Зачем.** Освещение шахты становится экономикой (уголь), темнота —
реальной угрозой, а не косметикой; связывает добычу угля, исследование и
бой.

### 4. Давление и динамика воды (`src/mechanics/water.rs`)
**Как работает.** Вода течёт по уровням (источник → 1..7), падает вниз,
два источника рядом над опорой создают новый источник, течение пересыхает
без источника. Обновления идут очередью по тикам (20/с, бюджет 300 клеток
за тик). В мире есть **подземные водоносные слои** — затопленные полости.
Если над клеткой воды столб из 3+ блоков, вода размывает соседние слабые
блоки (земля, песок, гравий, глина): шахта, прорытая рядом с водоносным
слоем через рыхлую породу, может внезапно затопиться. Ведро зачерпывает и
выливает источники.

**Зачем.** Добавляет риск и планирование: копать рядом с водой нужно через
камень, а не через гравий; затопление — ещё одна причина ставить крепи и
укреплять стены.

### 5. Мутации мобов по глубине (`src/entities/mob.rs`)
**Как работает.** Моб, появившийся ниже y=42/26/12, получает уровень мутации
1/2/3 (с небольшим разбросом): здоровье ×(1+0,5·L), урон ×(1+0,35·L),
скорость ×(1+0,1·L), размер больше, фиолетовый оттенок, светящиеся глаза,
на 3-м уровне — регенерация. Имя показывает уровень: «Мутировавший»,
«Искажённый», «Глубинный».

**Зачем.** Глубина = награда (алмазы, резонит) и риск; прогрессия
снаряжения ощущается естественно.
